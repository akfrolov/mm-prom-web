## Область и границы фичи

**Входит:** коллекция `articles` (4 файла `src/content/articles/*.md` + схема в
`src/content.config.ts`); обложки статей в `public/assets/articles/`; страница
списка `src/pages/blog.astro` (замена заглушки); шаблон статьи
`src/pages/blog/[slug].astro`; снятие noindex раздела; появление раздела и
статей в sitemap; OG-изображение/og:type для статей (минимальное расширение
пропсов `BaseLayout`).

**Не входит** (соседние фичи, см. §2.8): шапка/мегаменю/мобильное меню, подвал,
favicon, шрифты (фича `site-shell`), общие стили и повторяющиеся компоненты
страниц (фича `site-pages`), карточки объектов (фича `object-card`), запись
`/blog/` в канон-таблицу CR-2026-001 и правки AGENTS/DESIGN/REGRESSION
(шаг `docs`), план форм заявок (вне CR).

## 6. Решения агента — на ревью владельца

1. **Хранение статей — content collection `src/content/articles/*.md`** со
   свежими frontmatter (title/lead/date/source/cover): в заметках
   `docs/notes` только `creator: USER`, модель §2.1 — проект под целевые
   требования; имена файлов = слаги из CR.
2. **Теги и блок автора не выводятся:** в п. 28 перечислены «текст, обложка,
   дата, время чтения, ссылка на первоисточник»; тегов/автора в данных нет.
   Демо-мокап с тегами/автором читается как образец вёрстки на будущее.
   Из мета остаются дата и время чтения (в карточках — плюс excerpt).
3. **Тексты заметок переносятся как есть**, включая опечатки («Подробнее —на»,
   обрыв «Редакция» в заметке «Строительный рынок под давлением») — правка
   текстов вне скоупа спеки; строка «Подробнее …» в тело не переносится —
   заменяется блоком первоисточника (п. 28 требует явную ссылку).
4. **Рубрики-табы и поиск макета не входят в v0** (§2.4 п. 5) — для 4 статей
   без рубрик механика не имеет данных; вернуть при расширении раздела.
5. **OG-механика — опциональные пропсы `ogImage`/`ogType` в `BaseLayout`**,
   добавляемые шагом B2 (файл BaseLayout закреплён за `site-shell`, но его
   шаг выполняется раньше и OG-пропсы не реализует): `og:type=article`,
   `og:image`=обложка; дефолты не меняются. Альтернатива — дублирование
   мета-тегов в head-слоте страницы — отвергнута (двойные og:image).
   Синхронизация с фичей `object-pages`: если `object-pages` добавит те же
   пропсы раньше — переиспользовать их.
6. **Порядок карточек — по дате убыв., без даты в конце** (§2.4 п. 4); CR
   порядок не задаёт.
7. **Время чтения — честная формула `max(1, ceil(words/200))`** → все четыре
   статьи показывают «1 мин чтения» (объём заметок 100–152 слова). «6 мин
   чтения» из мокапа — демо-значение другого (кейс-)текста.
8. **Первоисточник в списке не выводится** (в мета-строке карточки дата и
   время чтения); ссылка издания — только на странице статьи (п. 28 формулирует
   её как атрибут страницы статьи).
9. **Названия изданий** в блоке первоисточника: «Rustempo.ru» / «Российская
   газета» / «Анатомия бизнеса» / «Abnews.ru» (по заметкам §1.4); CR фиксирует
   только домены — текстовые метки уточняются дельтой.
10. **Meta-description списка — lead-текст макета** («Экспертные статьи и
   кейсы об индустриальной недвижимости…»); слова «Telegram» в мете нет —
   п. 24 требует корректное написание, если упоминание появится.
