# Часть 03 — W1.3: мобильные отступы <768px через переменные (CR п. 20)

Источник правки: CR-2026-002 п. 20; SPEC §1.4, §2.1 (строка «Мобильные отступы»).

## Было → Стало

| Было | Стало |
|------|-------|
| Боковые отступы `.container` — 32px на всех ширинах <1024 (development.astro:60–62); на 767.98 и слабее — тоже 32px | На <768: у первого экрана (`hero`) — 24px, у блоков ниже — 16px; на 768–1023 — 32px, ≥1024 — 40px (как сейчас) |
| Отдельных мобильных правил для hero нет (`b-hero__inner` не упомянут в медиа <768 development.astro:807–820) | В `public/assets/blocks.css` (создаётся в W2.1, часть 04) добавлен мобильный блок — код ниже |
| Бегущая строка — от края до края (`.b-marquee` padding 14px 0, без боковых) | Без изменений: правило `.container` на бегущую строку не влияет (разметка маркера вне `.container`, index.astro) |

Добавляемый блок в `blocks.css`:

```css
@media (max-width:767.98px){
  :root{ --pad-hero-m:24px; --pad-side-m:16px; }
  .container{ padding-left:var(--pad-side-m); padding-right:var(--pad-side-m); }
  .container.b-hero__inner{ padding-left:var(--pad-hero-m); padding-right:var(--pad-hero-m); }
}
```

Механика и почему так:

1. Правка живёт в `blocks.css` — одном файле (правка вида блока вносится один
   раз), а не копией в 22 страницах. Пиксели не пишутся в разметку — только
   переменные `--pad-hero-m` и `--pad-side-m` (§2.1: «через переопределяемые
   значения, не фиксируя пиксели в разметке»).
2. Хиро-контейнер — `container b-hero__inner` (разметка hero, например
   development.astro:842/848; он есть на 18 страницах — index, about, contact,
   uslugi, 10 услуг, 4 роли; у atlas, avrora, blog, katalog первого экрана
   нет — их контент-секции получают 16px базовым правилом `.container`).
   Правило для хиро-контейнера пишется после правила `.container` в том же
   медиа-блоке — каскад внутри одного файла детерминирован.
3. Значения 24px/16px взяты из постановки п. 20 «на ревью владельца» —
   переменные меняются в одном месте blocks.css.
4. На 768px и выше ни одно из двух правил не действует (медиа <768); отступы
   32/32/40 сохраняются через существующие базовые правила.

Не трогается: вертикальный `padding` hero (`clamp(40px,6vw,72px) 0`,
development.astro:197 — меняются только боковые), `.section`/`.b-cta`
вертикальные отступы, брейкпоинт-написания `767px`/`767.98px` в страницах
(§6.7 — не унифицируются).
