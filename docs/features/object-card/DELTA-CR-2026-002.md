## Цель изменения

Карточки объектов перестают вести на битые и внешние заглушки: каждая карточка
ведёт на страницу своего объекта, чип типа окрашивается фирменным цветом своего
типа, фото читается без дублирующей подписи, стрелка — без неожиданного
подчёркивания. Каталог из списка кнопок «открыть модалку» превращается в список
прямых переходов на страницы объектов.

## Контекст для исполнителя

- Компонент один — `src/components/ObjectCard.astro` (98 строк), две ветки:
  ленточная (`showMap = false`; вызовы: `index.astro:829/836/843`,
  `arenda.astro:908`, `prodazha.astro:902`) и каталожная
  (`katalog.astro:893`, проп `showMap`). Внутри файла `d = obj.data`; id записи
  — `obj.id` (строки 20, 37, 52), поля `d.id` в файле нет.
- Сейчас href строится из данных (`ObjectCard.astro:12`):
  `const href = d.link || d.external || ''`. Содержимое полей у 9 карточек лент:
  у antares / parnas / volhonskoe / voyskovitsy-park `link = '/kartochka-obekta/'`
  (битая), у land-tervolovo `link = '/katalog/'` (заглушка), у land-koltushi /
  land-volosovo — внешние URL invest-platforma.com с `linkExternal: true`.
  В целевом рендере эти поля не читаются вовсе (чистка данных — фича
  `objects-data`).
- Брендбуки: id записей `atlas-garazhny` и `avrora-vitebsky` (без «j» на конце),
  целевые маршруты — `/atlas-garazhnyj/` и `/avrora-vitebskij/` (с «j»).
  Слаг маршрута не равен id записей — в компоненте нужен явный маппинг.
- Схема (`src/content.config.ts`): `type` — обязательный enum
  `['park','warehouse','production','land']` (строка 12), `typeLabel` —
  обязательный текст (строка 13); `badgeLabel`/`badgeClass` — optional
  (строки 30–31); `link`, `linkExternal` — optional, `external` — обязательная
  строка, часто пустая (строки 25, 32, 33).
- Правило cache-busting: правки `object-card.css` сопровождаются bump `?v=` в
  тегах подключения на 4 страницах (`index.astro:13`, `arenda.astro:12`,
  `prodazha.astro:12`, `katalog.astro:14`, сейчас `?v=1`).
- Что НЕ трогать из работающего MVP — см. «Инварианты» ниже.

## Блок W3.1 — Ссылка на страницу объекта в обеих ветках

**Источник:** CR-2026-002 п. 8 (стр. 84–86) и раздел «Страницы объектов»
CR (стр. 152–165); спека §6.1 (стр. 114–125), §3 (стр. 39–49, 53–59),
§4 (стр. 77–84), §7 (строка «Ссылки»).

**Пункты:**

- ИЗМЕНИТЬ [спека §3, `ObjectCard.astro:12–13` и `:79`] — href стрелки-ссылки
  `a.obj-card__link` строится из id записи, а не из полей данных:
  - Было: `const href = d.link || d.external || ''` — рендерятся битая
    `/kartochka-obekta/` (×4), заглушка `/katalog/` (×1), внешние
    invest-platforma.com (×2).
  - Стало: id = `atlas-garazhny` → `/atlas-garazhnyj/`; id = `avrora-vitebsky`
    →     `/avrora-vitebskij/`; остальные записи → `/obekt/<id>/`.
- ИЗМЕНИТЬ [обе ветки, `ObjectCard.astro:50` и `:79`] — `target="_blank"` (и
  `rel="noopener"`) не ставится ни в одной ссылке карточки: все цели внутренние,
  в том числе «На страницу объекта» у брендбуков ведёт на внутренний маршрут
  (было — внешние mm-prom.ru). `aria-label` стрелки сохраняется.
- ИЗМЕНИТЬ [спека §4, `ObjectCard.astro:49–52`] — каталожный foot:
  - Было: если `d.external` непуст — `<a class="obj-card__ext"
    href={d.external} target="_blank">` «На страницу объекта» (atlas/avrora),
    иначе `<button class="obj-card__more" type="button" data-open={obj.id}>
    Подробнее` (25 объектов; клик открывает модалку `#obj-modal`).
  - Стало: у 25 не-брендбуков — `<a>` «Подробнее» на `/obekt/<id>/`, разметки
    кнопки и `data-open` больше нет; у 2 брендбуков — `<a>` «На страницу
    объекта» на внутренние `/atlas-garazhnyj/`, `/avrora-vitebskij/`. Классы
    сохраняются (`obj-card__more` / `obj-card__ext`), чтобы вид foot не
    изменился; условие выбора ветки — по id записи, не по `d.external`.
- ИЗМЕНИТЬ [спека §6.1] — значения `d.link`, `d.external`, `d.linkExternal` из
  рендера не читаются (ни в href, ни в ветках); чистка полей в данных и схеме —
  фича `objects-data`, здесь ничего в `src/content.config.ts` и
  `src/content/objects/*.json` не менять.

Пример I/O (логика href):

вход `obj.id = 'antares'` → выход `href = '/obekt/antares/'`, без `target`;
вход `obj.id = 'atlas-garazhny'` → `'/atlas-garazhnyj/'`;
вход `obj.id = 'land-koltushi'` → `'/obekt/land-koltushi/'`
(сейчас: `https://invest-platforma.com/…`, `target="_blank"`).

**Новые TC (принадлежат блоку):**

- TC-OC-01 (рендер, `astro preview` + Playwright): ленточные карточки antares,
  parnas, volhonskoe, voyskovitsy-park на `/`, `/arenda/`, `/prodazha/` ведут
  на `/obekt/<id>/` — бывшие `/kartochka-obekta/` нигде не кликаются.
- TC-OC-02 (рендер): ленточные карточки atlas-garazhny и avrora-vitebsky ведут
  на `/atlas-garazhnyj/` и `/avrora-vitebskij/`; плашка «Презентация» при этом
  сохранена.
- TC-OC-03 (рендер): в каталоге у не-брендбуков foot — ссылка «Подробнее»
  (элемент `a`, не `button`) на `/obekt/<id>/`; у брендбуков — «На страницу
  объекта» на внутренние маршруты; `data-open` в разметке карточек отсутствует.
- TC-OC-04 (рендер): на `/`, `/arenda/`, `/prodazha/`, `/katalog/` нет ссылок
  из карточек на `/kartochka-obekta/`, на заглушку `/katalog/` (цель
  land-tervolovo «было») и на invest-platforma.com; ни одна ссылка карточки
  не открывается в новой вкладке.

**Критерии приёмки (механические):**

- Grep `ObjectCard.astro`: есть `/obekt/`; нет `data-open`; нет
  `target: '_blank'` и `target="_blank"`.
- Grep `ObjectCard.astro`: `d.link`, `d.external`, `linkExternal` не
  используются в расчёте href и в ветке foot.
- Grep вывода сборки (или preview): карточки содержат `href="/obekt/<id>/"`
  (пример: antares → `/obekt/antares/`); `data-open` на страницах отсутствует.

**Якорь эталона:** SPEC.md §6.1 (стр. 114–125); CR п. 8 (стр. 84–86).
Мокапы `docs/mockups/*` ссылок `/obekt/` не содержат (карточки ведут на

## Блок W3.2 — Чип типа цветом своего типа; канон цветов в object-card.css

**Пункты:**

  обязательных `d.type` и `d.typeLabel`, без обходного бейджа из данных:
