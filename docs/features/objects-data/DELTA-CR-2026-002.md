## Цель изменения

Каталог отстал от новой версии сайта: нет шести объектов, данные существующих
устарели, фото тянутся с чужого хостинга, часть карточек ведёт на ссылки-заглушки.
После дельты каталог показывает все 33 объекта актуальной версии сайта
с фотографиями с самого сайта, а ссылочные поля данных готовят карточки
к переходу на страницы объектов.

## Контекст для исполнителя

- Суть: правка только данных и схемы. Источник значений — снапшот новой версии
  сайта `.kilo/scripts/sources/mm-prom-site-2026-10-23/catalog-data.js`
  (`window.CATALOG_OBJECTS`, 32 записи; `voyskovitsy-park` в снапшоте нет —
  он сохраняется отдельно, решение владельца: это другое предложение).
- Ключи снапшота ↔ поля схемы: `loc` → `location`; `dealTypes` выводится из
  `deal` («Аренда» → `rent`, «Продажа» → `sale`); `priceNote` не переносится
  (во всех 32 записях пусто); `group` — аналог в схеме отсутствует, не переносится.
  `areaNum`: число снапшота берётся как есть, значение `0` в снапшоте означает
  «площадь не указана» → в коллекции `null` (ноль сломал бы фильтр/сортировку).
- Фото шести новых объектов уже лежат в `public/assets/objects/<id>/cover.jpg…`
  (состав файлов один-в-один с массивами `images` снапшота) — загрузки не нужны.
- Соответствие «внешний URL → локальный файл» для 19 URL — в
  `.kilo/scripts/sources/mm-prom-site-2026-10-23/map-external.tsv` (19 строк;
  правая часть `public/assets/external/inv-*` → в JSON путь с ведущим слэшем).
- НЕ трогать из работающего словаря данных: код страниц и компонентов;
  `presentation` брендбуков (`/gejt-broshury/` — известная битая ссылка, не чинить);
  `placeholder`, `cardDesc`, `meta`, `badgeLabel`/`badgeClass` — сохраняются;
  `hero`/`faq`/`cta`/`searchTitle` не заполняются (фича `object-pages`).

### W1 — Схема: поле `images`, `external` — необязательное

| Параметр | Значение |
|----------|----------|
| Затрагиваемые файлы | `src/content.config.ts` |
| Источник | CR «Влияние на данные/миграции» (поле `images`, `external` optional); спека §6.3, §6.4 |
| Якорь эталона | спека §6 (п. 3, 4); ACCEPTANCE.md §2 («поле `images` (галерея; массив строк)») |

**ДОБАВИТЬ**

1. Поле `images` — необязательный массив строк путей галереи: `images: z.array(z.string()).optional()`.
   Путь — с ведущим слэшем от корня сайта (`/assets/objects/<id>/cover.jpg`).
   Первый элемент — основное фото галереи (обложкой карточки остаётся `image`).

**ИЗМЕНИТЬ**

2. Поле `external` — из обязательного в необязательное.

   Было: `external: z.string(),`
   Стало: `external: z.string().optional(),`

**До → после (I/O)**

- вход: запись JSON без поля `external` → сборка проходит,
  `getCollection('objects')` отдаёт запись;
- вход: запись с `"images": ["/assets/objects/rabochaya/cover.jpg", …]` →
  валидно; у записи есть массив путей галереи;
- вход: текущие 27 записей (у всех есть `external`) → валидны без правок.

**Новые TC:** TC-OD-001, TC-OD-002.
**Критерии приёмки (механические):** grep `images: z.array(z.string()).optional()`
и `external: z.string().optional()` в `src/content.config.ts`; `npm run build`
и `npx astro check` зелёные на 33 записях.

данные для будущей галереи страницы объекта. CR (раздел «Влияние
на архитектуру»): ADR не требуется.

## Решения агента — на ревью владельца

1. **`sort` новых записей** — 27…32 в порядке перечисления CR п. 25
   (rabochaya 27, nevelskaya 28, kolpino 29, metallostroy 30, murino 31,
   ip-razmetelevo 32). Порядок вывода в каталоге при желании меняется
   значениями на приёмке.
2. **`areaNum: 0` → `null`.** В снапшоте нулём помечены 24 записи, включая те,
   у которых в коллекции сейчас есть числа (например atlas-garazhny 8577 →
   снапшот 0). Фильтр/сортировка по площади после синхронизации обеднеет —
   это поведение новой версии сайта; альтернатива (сохранить текущие числа
   для таких записей) — вопрос ревью.
3. **Расхождения старых `busy`/`areaNum` со снапшотом** принимаются
   («синхронизировать со новой версией»); заметные смены ярлыка «Нет площадей»
   (сейчас busy ×4) перечислить на приёмке каталога.
4. **Поля без аналога в снапшоте** (`media`, `badge*`, `cardDesc`, `meta`,
   `placeholder`) сохраняются как есть; `external` у не-брендбуков остаётся
   пустой строкой (25 файлов) — минимальный diff.
5. **`image` antares/atlas/avrora** берётся из снапшота
   (`/assets/objects/<id>/cover.jpg`, директории уже в `public/`), а не по
   hash-копиям из §6.6 — hash-копии (`9d4c4a14-`, `ade44b54-`, `7da0587c-`)
   применяются к `media.src`. Отличие от буквального чтения §6.6 для `image`
   — на ревью; итоговый критерий (нет внешних URL) соблюдается в обоих вариантах.
6. **Сверка локации в TC-OD-004** — по значению `loc` снапшота, а не по
   префиксу адреса: адреса в снапшоте неоднородны (`spb` — «Санкт-Петербург…»,
   но и «г. Пушкин…»; `lo` — «Ленинградская обл.»/«Ленинградская область»/«ЛО»,
   а у `ip-razmetelevo` адрес начинается с «дер. Разметелево»).
